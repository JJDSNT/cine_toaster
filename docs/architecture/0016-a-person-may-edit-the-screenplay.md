# ADR 0016: A person may edit the screenplay; the program still never rewrites it

Status: accepted. Amends [ADR 0006](0006-authored-and-runtime-files.md).

## Context

ADR 0006 forbids Cine Toaster to rewrite a file a human authored, because
reading a file into a model and serializing it back destroys comments, notes
and layout. The screenplay is on its list.

Plan step 8 is a screenplay editor. Writers need to change the screenplay
where they see it next to the shots that cover it (SPEC-0006). The prohibition
was never about who holds the pen. It was about software rewriting text on its
own terms.

SINGULAR adds a second fact. Its screenplay (`roteiro/v4`) is generated by
`monta_v4.py` from the author's V3. An edit made in an editor would be
overwritten the next time it is assembled.

## Decision

**A person may edit a screenplay file through Cine Toaster. The runtime writes
the text that person wrote, byte for byte, and nothing else.**

- **Text in, text out.** The editor sends the full text of one file. The
  runtime writes exactly that text, with no parsing and no reserializing, so
  nothing the person did not touch can change. Two conventions of the
  original file are restored: its line endings (CRLF) and its byte-order
  mark, because an editor normalises them without the person choosing to.
- **Screenplay files only.** The command accepts only a file that the
  production reads as its screenplay (`paths.script`). Breakdowns,
  `project.yaml` and world files remain never written, as ADR 0006 says.
- **Revision checked.** The editor sends the hash of the text it opened. If
  the file changed since (another editor, a generator, a `git pull`), the
  write is refused as a conflict and nothing is overwritten.
- **Atomic.** A temporary sibling, `fsync`, then `os.replace`, as for runtime
  state.
- **Generated screenplays are read only.** A production declares
  `screenplay_generated_by: <what makes it>`. The editor then opens the files
  read only and says what to change instead. A read-only production
  directory is refused the same way.
- **Recorded.** Each write emits a `screenplay.edited` event with the file,
  the hashes before and after, and the actor. The production's own version
  control holds the history.
- **Impact shown.** The command returns what the edit did to the film's
  links: anchors that no longer resolve, lines that drifted, dialogue that
  no shot covers.
- **Agents propose, people apply.** An agent may draft a change, but a
  person saves it through this command. There is no agent write path.

## Consequences

- ADR 0006's guarantee stays true in the form that matters: no file is
  rewritten by software on its own initiative, and no byte a person did not
  change is touched.
- Shots anchor to screenplay text (SPEC-0006). Editing a quoted line can
  break a `covers` anchor, and the impact report and `toast check` show it at
  once.
- A multi-file screenplay is edited one file at a time. Each file has its
  own revision check.
